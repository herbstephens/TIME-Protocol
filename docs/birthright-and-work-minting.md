# Birthright and Work Minting

## Summary

TIME issuance is built around a dual stream:

1. **Birthright TIME** — the protocol-level UBI floor.
2. **Work TIME** — payment-triggered issuance for verified human labor.

Together they respect the biological constraint:

```text
maximum new issuance = 24 TIME / verified human / day
```

## Birthright TIME

Birthright TIME gives each verified human a baseline daily allocation.

It is not charity. It is protocol-level recognition that every human enters the economy with the same finite daily resource: time.

Recommended baseline:

```text
1 TIME / day / verified human
```

## Why Birthright Exists

Birthright TIME provides:

- economic floor;
- network bootstrap;
- universal participation;
- governance voice;
- liquidity for local allocation;
- signal that humans, not capital, are the base unit.

## Work TIME

Work TIME is minted when work is paid.

The work minting sequence:

```text
1. Worker verifies humanity.
2. Payer creates or accepts a work agreement.
3. Worker reserves a non-overlapping time block.
4. Payer funds escrow or makes payment.
5. Work is completed or accepted.
6. Protocol confirms payment.
7. TIME is minted to worker.
8. Soulbound Work NFT records the event.
```

## Mint Event

```text
Payment for work is the mint event.
```

This phrase should be canonical.

It distinguishes TIME from:

- unbacked social credit;
- unpaid labor points;
- speculative token emissions;
- fiat-backed stablecoins;
- capital-backed governance tokens.

## Anti-Fraud Requirements

A credible TIME minting system must prevent:

- duplicate identities;
- double-booked time;
- unpaid work claims;
- fake payer/worker loops;
- wash payments;
- unverifiable labor claims;
- bot or AI impersonation of human work.

## Work NFT Metadata

Each Work NFT may contain or selectively disclose:

- worker nullifier or pseudonymous identifier;
- payer identifier;
- work category;
- jurisdiction;
- timestamps;
- payment proof;
- number of verified hours;
- dispute status;
- credential tags;
- optional encrypted description.

## Retroactive Birthright Question

Some repo concepts propose retroactive birthright TIME from birth.

This is powerful but controversial.

Recommended framing:

### Conservative Launch

```text
Birthright accrues only after verification.
```

### Expansion Path

```text
Retroactive birthright can be introduced by governance after anti-Sybil, identity, and distribution risks are solved.
```

## Key Invariant

```text
No verified human can mint more than 24 new TIME per day.
```

This is the atomic supply rule.

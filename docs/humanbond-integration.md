# HumanBond Integration

## Summary

HumanBond is a reference application for TIME Protocol in the domain of relationships.

It demonstrates that TIME is not only for wage labor. TIME can also represent verified human commitment, shared life, household governance, and relationship history.

## Core Primitive

```text
Two World-ID-verified humans.
One cryptographic bond.
Shared TIME yield.
Soulbound relationship history.
Clean exit.
```

## Components

| Component | Purpose |
|---|---|
| Bond | two verified humans create a relationship contract |
| Vow NFT | soulbound proof of relationship |
| Daily TIME yield | TIME issued for time together |
| Milestone NFT | yearly relationship record |
| Treasury | optional two-person DAO finance |
| Divorce / clean exit | preserves history, splits pending yield, unlocks future bonds |
| Registry API | privacy-preserving proof of relationship status |

## Why It Matters to TIME

HumanBond expands TIME from work to life.

TIME Protocol can represent:

- paid work time;
- volunteer time;
- care time;
- relationship time;
- governance time;
- civic time.

This makes TIME a broader human coordination primitive.

## Suggested TIME Rules

A conservative version:

```text
A verified bond may receive 1 TIME/day together, split 50/50.
```

This TIME should be categorized separately from work-earned TIME if needed.

Possible categories:

- `birthright_time`
- `work_time`
- `bond_time`
- `volunteer_time`
- `governance_time`

## Relationship Proofs

The relationship registry should support privacy-preserving queries:

```text
Is this verified human currently bonded?
Is this bond active?
Has this bond ended?
When did this bond begin?
```

Users should control what is disclosed.

## Two-Person DAO

A HumanBond can become a two-person DAO with:

- shared treasury;
- spending rules;
- income split;
- multi-sig thresholds;
- household budgeting;
- property records;
- child/care commitments;
- exit process.

## Clean Exit

A good human contract must make exit possible.

Clean exit should:

- distribute pending yield;
- preserve history;
- prevent deletion or falsification;
- allow cooldown;
- reset eligibility for future bonds.

## Design Warning

Relationship TIME should not create incentives for coercion, fraud, or dependency.

A credible implementation needs:

- consent from both parties;
- unilateral exit;
- privacy;
- abuse safeguards;
- no transferable relationship NFTs;
- clear separation from legal marital status unless explicitly integrated.
